# Session plans

Use ordinary requests to plan a session; no slash command is required. Plans should be bounded by one useful outcome rather than a compulsory one-day lesson or invented benchmark.

The original [day-01.md](day-01.md) is historical. The active next plan is [session-02.md](session-02.md).

Template:
- Outcome and roadmap/JD mapping.
- Observed prerequisites, existing edits, and assumptions.
- Small implementation steps the assistant may execute.
- Acceptance checks and relevant failure case.
- Explanation/walkthrough to deliver.
- Optional understanding checkpoint.
- Actual results, deferred work, and next step at session end.

Implementation may proceed while an optional learning question is pending. Track pending understanding separately from unfinished engineering.
