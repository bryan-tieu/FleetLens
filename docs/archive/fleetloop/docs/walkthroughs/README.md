# Feature walkthroughs

Write these for Bryan after a substantial feature is implemented. A walkthrough explains real code and observed behavior, not a future success story.

Use: problem and JD row; status and relevant files; concrete input/output; step-by-step data flow; core design and alternative; verification evidence; failure example; limitations; short teach-back questions; evidence-supported interview wording.
