# Interview evidence and practice

Use the [JD map](../jd-map.md) to choose relevant questions and the [learning ledger](../learning/README.md) to identify gaps.

For each actual exercise record the question, Bryan's response (verbatim only if supplied), assistance level, assessment with reasons, a corrected model answer, and one follow-up. Keep model answers distinct from his answers. Do not infer proficiency because the assistant explained a topic.

Completed-tense claims require an implemented artifact and appropriate verification or measurement. Future designs are phrased as plans; never rehearse invented numbers as achievements.

AI assistance may be described honestly: explain what Bryan decided, reviewed, validated, and can now debug or change. Do not imply a real production fleet, professional team experience, or an integrated telemetry-to-training loop without evidence.

Suggested coverage: trace a record end to end; defend table grain/ordering; explain replay after partial failure; compute and qualify a metric; diagnose a semantic schema change; explain selection bias; inspect evaluation leakage; modify a small Python function or SQL query; discuss an actual negative result.
